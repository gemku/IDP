## Why

A comprehensive codebase review revealed three operational reliability and edge-case failure modes:
1. `LdapService` swallows unhandled socket connection errors (`client.on('error')`), causing pending requests to hang indefinitely on network/DNS failure instead of immediately rejecting with a 503.
2. In `repos.ts`, non-numeric `page`, `limit`, or `teamId` query parameters evaluate to `NaN` through `parseInt`, causing `Math.max(1, NaN)` to propagate `NaN` into pagination calculations and array slices, or producing misleading `403 Forbidden` responses.
3. In `gitlab-tag-sensor.yaml`, `eventSourceName` is hardcoded as `gitlab-eventsource`, whereas `gitlab-tag-trigger-rgd.yaml` dynamically provisions `<trigger-name>-eventsource`, causing sensors to fail to match events generated by per-repo triggers.

## What Changes

- **LDAP Connection Error Handling**: Update `LdapService.getUserGroups` to handle socket-level `'error'` events before and during bind/search, rejecting immediately with `LDAP Connection Error` to prevent hung connections.
- **Query Parameter Sanitization & Type Safety**: Add numeric validation and defensive defaults for `page`, `limit`, and `teamId` query parameters in `repos.ts`, returning `400 Bad Request` on invalid numeric values or falling back safely without producing `NaN`.
- **LDAP Group Query Deduplication**: In `DatabaseManager.findActiveTeamsForUser`, deduplicate input LDAP DNs using `Array.from(new Set(...))` to avoid redundant SQL parameter placeholders.
- **Argo Sensor EventSource Alignment**: Align `gitlab-tag-sensor.yaml` event source dependency name with the KRO ResourceGraphDefinition event source convention or provide a unified shared event source name.
- **Graceful Server Port Error Handling**: Add error listener in `server.ts` to log an informative message and exit cleanly if the configured port is already in use (`EADDRINUSE`).
